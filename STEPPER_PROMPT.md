## 4. The data contract

This section is the specification. Java writes exactly this, and Elm accepts exactly this. Copy
§4.1–§4.3 into `docs/TRACE.md`.

### 4.1 File shape

The file is pure ASCII JSON. `Trace` escapes every char `< 0x20` or `> 0x7E` as `\u00XX`, so
encoding never matters.

```json
{
  "format": "parva-trace",
  "version": 1,
  "file": "test10length.pav",
  "source": "void displayList() {\r\n...",
  "maxT": 53,
  "memSize": 812,
  "terminals": ["EOF", "identifier", "number", "..."],
  "types": ["none", "none[]", "null", "null[]", "int", "int[]", "..."],
  "ops": [ {"name": "ABS", "words": 1}, {"name": "BRN", "words": 2}, "..." ],
  "events": [
    {"i": 0, "ev": "scope.open", "at": null, "depth": 1},
    {"i": 1, "ev": "scan", "at": null, "tok": {"kind": 5, "val": "void", "line": 1, "col": 1, "pos": 0}, "pragma": false},
    "..."
  ]
}
```

The header fields and how to compute them:

| Field | How to compute it |
|---|---|
| `source` | Read the `.pav` as **bytes decoded with ISO-8859-1**. Coco's `Buffer` counts bytes, so `pos` then indexes `source` exactly. |
| `terminals` | Index = token kind. Use reflection over `Parser`'s `static final int` fields whose names end in `_Sym` or `_SYM`, and strip the suffix. Fill gaps with `"kind<n>"`. Pragmas (kinds > `maxT`) are included. |
| `types` | Index = type id. Copy `Types.typeNames`. |
| `ops` | Index = opcode `0..PVM.nul`. `name = PVM.mnemonics[op]`. `words = 2` for exactly the two-word opcodes listed in `PVM.listCode`'s switch (`bfalse btrue brn bze sfd sfu efd efu dsp lda ldc ldl stl stlc ston`) **plus `prns`**, whose operand is a string address. Otherwise `words = 1`. Keep that list in one array in `Trace.java`, referencing `PVM.*` constants. |
| header in general | Build it **at finish time**, after `PVM.init`/`Table.init` have run. Do not build it at start. |

### 4.2 Events

Every event has `i` (0-based, contiguous), `ev` (the kind) and `at`. `at` is `[line, col]` of
the **last consumed token**, or `null` before the first one is consumed. The other fields
depend on `ev`:

| `ev` | Extra fields | Emitted from |
|---|---|---|
| `scan` | `tok`, `pragma` (`tok.kind > maxT`) | `Parser.frame` `Get()`, right after `la = Scanner.Scan()` |
| `consume` | `tok` | `Parser.frame` `Get()`, first statement. **Skip the dummy token** that `Parse()` primes `la` with (`line == 0`). |
| `enter` | `prod` | production method start (added by `Instrument`) |
| `exit` | `prod` | production method `finally` (added by `Instrument`) |
| `scope.open` | `depth` = number of scopes after opening (the first is 1, from `Table.init`) | `Table.openScope` |
| `scope.close` | `depth` = number of scopes after closing | `Table.closeScope` |
| `sym.insert` | `sym`, `depth`, `clash` (= `earlierEntry.declared`) | end of `Table.insert` |
| `sym.find` | `name`, `found` (= `entry.declared`), `sym` only if found | `Parva.atg` `Designator`, after `Table.find` |
| `check` | `rule`, `args` (type *names*), `ok` | `Parva.atg` helper functions, and `Trace.that` |
| `mem` | `addr`, `old`, `new`, `cause` ∈ `emit` `patch` `fixdsp` `string` | `CodeGen` (5 places) |
| `diag` | `severity` ∈ `syntax` `semantic` `warning`, `line`, `col`, `msg` | `Errors` class in `Parser.frame` |
| `end` | `ok`, `errors`, `warnings`, `codeLength`, `initSP`, `code` (`PVM.mem[0 .. codeLength-1]`), `strings` (`PVM.mem[initSP .. memSize-1]`), `selfCheck` | driver (`Parva.frame`) after `listCode` |
| `abort` | `reason`, `selfCheck` | `Trace` itself (uncaught exception, `System.exit` before `end`, event limit, internal error) |

Two sub-shapes recur:
- `tok = {kind, val, line, col, pos}`, copied from `Token`. Do not trust the "col starts at 0"
  comment in `Scanner.java`. Record the values as they are; Elm uses `pos` for highlighting.
- `sym = {name, kind: "const"|"var"|"func", type: <type name>, value, offset}`. Take `kind`
  from `Kinds.kindNames` with the padding trimmed.

**Exactly one terminal event (`end` or `abort`) exists, and it is last.**

### 4.3 Invariants: what "a good trace" means

`Trace.java` checks the cheap invariants as it goes (its *self-check*). `Machine.elm` checks
all of them again, because a file may have been edited or truncated. A trace is rejected at
the first violation, with the event index and a one-line reason. **The view never renders a
rejected trace.**

| # | Invariant | Catches |
|---|---|---|
| I1 | `i` equals the event's array index | truncated or merged files |
| I2 | exactly one `end`/`abort`, and it is last | crash or missed finish |
| I3 | **LL(1) discipline:** a non-pragma `scan` requires no pending lookahead, and then that token becomes pending. A `consume` requires a pending lookahead with equal `pos` and `kind`, and then clears it. A pragma `scan` never becomes pending. | wrong hook placement in `Get()` |
| I4 | for `scan` with non-empty `val`: `String.slice pos (pos + length val) source == val`, and `pos` never decreases | position or encoding bugs |
| I5 | `exit p` requires the open node to be `p` and not the synthetic root | Instrument bugs |
| I6 | `scope.open` depth = current+1. `scope.close` depth = current−1 ≥ 0. `sym.insert` depth = current ≥ 1. | missing scope hooks |
| I7 | every `mem.old` equals the current shadow value (memory starts all-zero; `PVM.init` zeroes it) | **a memory write that was not hooked** |
| I8 | `emit` requires `addr == codeTop`, then `codeTop += 1`. `patch`/`fixdsp` require `addr < codeTop`. `patch` requires `new == codeTop` and `old` ∈ {−1} ∪ [0, codeTop). `fixdsp` requires `ops[mem[addr−1]].name == "DSP"`. `string` requires `addr == stringBottom − 1` (strings grow downwards from `memSize`) and `addr ≥ codeTop`. | misread back-patch chain |
| I9 | at `end`: `codeLength == codeTop`, the shadow code equals `end.code` and the shadow strings equal `end.strings`, the tree is closed (only the root is open), syntax+semantic `diag` count `== errors`, warning count `== warnings` | **the internal oracle: replay must reproduce the compiler's real output** |
| I10 | at `abort`: the state is kept as a partial trace with a banner. It is not an error. | — |

`selfCheck` is `"ok"` or the first Java-side violation of I3, I5, I6, I7 or I9. On violation,
`Trace` also prints `TRACE SELF-CHECK FAILED: <reason>` to **stderr** (never stdout, because
stdout is compared against the baseline).

### 5.1 New file `compiler/Parva/Trace.java` (package `Parva`, about 200 lines, JDK only)

```java

static void    mem(int addr, int oldWord, int newWord, String cause);
static void    diag(String severity, int line, int col, String msg);
static void    end(boolean ok, int errors, int warnings, int codeLength, int initSP);
```

Internal state:

| Field | Purpose |
|---|---|
| `ArrayList<String> events` | each event already serialised to one JSON line |
| `Token cur` | last consumed token → `at` |
| `ArrayDeque<String> prods` | open productions (I5) |
| `int depth` | scope depth (I6) |
| `int[] shadow` | `PVM.memSize + 1` zeros (I7, I9) |
| `String selfCheck` | first violation, or `null` |
| `boolean finished` | set when the file has been written |

Behaviour:
- `start` reads the source as described in §4.1, sets `on = true`, and installs two handlers.
  `Thread.setDefaultUncaughtExceptionHandler` writes `abort` with the exception class and
  message. A shutdown hook writes `abort "exited without end"` if the trace is not finished
  (this catches `System.exit` in `Errors.Exception`).
- `end` runs the I9 self-check against the real `PVM.mem`, writes the file, sets `finished`
  and turns `on` off.
- **Event limit 200 000** → `abort "event limit"`.
- The file is written once, at finish: header, then one event per line inside `"events": [ … ]`.
  This keeps it diffable.
- Write a single private `json(String)` escaper (`"` `\` and the `\u00XX` rule from §4.1). Do
  not use any other serialisation.

### 5.7 New tool `compiler/tools/Instrument.java` (production enter/exit, about 80 lines)

This runs after Coco/R, on `compiler/Parva/Parser.java` only.

## 6. Elm: shapes and the state machine

### 6.1 Processing pipeline (why no bad state can reach the view)

```
String ──decode──▶ Result String Trace ──build──▶ Result Problem Built ──▶ view (total functions)
        strict:                         fold with step; first violation
        unknown "ev" or missing         stops everything; Abort is a valid
        field = error; version must     end, not an error
        equal 1
```

| Layer | Guards against | Where |
|---|---|---|
| Java self-check | hooks placed wrongly *while developing* | `Trace.java`, `selfCheck` field |
| Bash equivalence | hooks changing compiler behaviour | `scripts/check.sh` |
| Elm decode + build | corrupt, edited or old-version files; anything Java missed | `Trace.elm`, `Machine.elm` |

### 6.2 `Stepper/Trace.elm` (input, immutable)

```elm
type alias Trace =
    { file : String, source : String, maxT : Int, memSize : Int
    , terminals : Array String, types : Array String, ops : Array OpInfo
    , events : Array Stamped }

type alias OpInfo  = { name : String, words : Int }                 -- words is 1 or 2
type alias Pos     = { line : Int, col : Int }
type alias Tok     = { kind : Int, val : String, line : Int, col : Int, pos : Int }
type alias Sym     = { name : String, kind : String, type_ : String, value : Int, offset : Int }
type alias Stamped = { i : Int, at : Maybe Pos, event : Event }

type Event
    = Scan Tok Bool                                   -- True = pragma
    | Consume Tok
    | Enter String
    | Exit String
    | ScopeOpen Int
    | ScopeClose Int
    | SymInsert Sym Int Bool                          -- depth, clash
    | SymFind String (Maybe Sym)                      -- Nothing = not found
    | Check String (List String) Bool
    | Mem { addr : Int, old : Int, new : Int, cause : Cause }
    | Diag Severity Pos String
    | End EndInfo
    | Abort String

type Cause    = Emit | Patch | FixDsp | StringData
type Severity = Syntax | Semantic | Warning
type alias EndInfo =
    { ok : Bool, errors : Int, warnings : Int, codeLength : Int, initSP : Int
    , code : Array Int, strings : Array Int, selfCheck : String }

decode : String -> Result String Trace
```

### 6.3 `Stepper/Machine.elm` (state and validation)

```elm
type alias State =
    { scanned  : Array ScanRec        -- every scanned token, in order
    , pending  : Maybe Int            -- index of the one unconsumed lookahead (I3)
    , tree     : Zipper
    , scopes   : List Scope           -- head = innermost
    , checks   : List CheckRec        -- newest first
    , mem      : Dict Int Int         -- shadow memory; absent key = 0
    , codeTop  : Int
    , strBottom: Int                  -- starts at memSize
    , lastMem  : Maybe Int            -- address written by this step (for highlighting)
    , diags    : List DiagRec
    , status   : Status }

type alias ScanRec  = { tok : Tok, pragma : Bool, consumed : Bool, atEvent : Int }
type alias Scope    = { depth : Int, syms : List Sym }
type alias CheckRec = { rule : String, args : List String, ok : Bool, atEvent : Int, at : Maybe Pos }
type alias DiagRec  = { severity : Severity, pos : Pos, msg : String, atEvent : Int }
type Status = Running | Finished EndInfo | Aborted String

-- Tree: a zipper with a synthetic root, so it can never be empty.
type alias Node   = { prod : String, kids : List Kid, enteredAt : Int }   -- kids newest first
type Kid          = KNode Node | KTok Int                                 -- KTok = index into scanned
type alias Zipper = { focus : Node, crumbs : List Node }                  -- crumbs = open ancestors, innermost first

type alias Problem = { event : Int, reason : String }
type alias Built   = { states : Array State        -- states[k] = after events 0..k-1; length = n+1
                     , matchExit : Dict Int Int    -- enter index → exit index (for "step over")
                     , matchEnter : Dict Int Int } -- exit index → enter index (for "step out")

step  : Trace -> Stamped -> State -> Result Problem State   -- enforces §4.3
build : Trace -> Result Problem Built                       -- all-or-nothing; I9 checked at End
```

Rules:
- `step` is the **only** function that creates a `State`.
- Every rule in §4.3 is one clearly named `Result` check inside `step`, with `reason` text
  taken from the table.
- Any event after `Finished`/`Aborted` is a `Problem`.
- Reject traces with more than 200 000 events before folding.

### 6.4 `Stepper/Derive.elm` (pure, total view helpers)

- `disassemble : Trace -> State -> List Instr`, where
  `Instr = { addr : Int, name : String, operand : Operand }` and
  `type Operand = None | Pending | Word Int | Str String`. `Pending` means a two-word opcode
  whose operand has not been emitted yet. Show it as `_`. `Str` reads the strings region
  downwards from the address until a 0 word.
- `listing : Trace -> State -> String` reproduces **exactly** the `.cod` format of
  `PVM.listCode` (`ASSEM`, `BEGIN`, `  {    0 } DSP      2`, …, `END.`). This makes the final
  state comparable by eye with `compiler/examples/*.cod`.
- `treeLines : Zipper -> List { depth : Int, label : String, open : Bool }` for an indented
  outline. Nodes on the open path are marked `open`.
- `sourceSpan : Trace -> State -> Maybe ( Int, Int )` gives the `pos` range of the pending
  lookahead and of the last consumed token.

### 6.5 `Stepper/Main.elm` + `View.elm` (MVP UI: functional, plain)

Use inline styles or one `<style>` node. No CSS framework. Support light and dark via
`prefers-color-scheme`.

- **Start screen:** list every embedded example with ✓, or ✗ plus its `Problem`. Add a
  "Load trace…" button (`elm/file`). Clicking a valid example opens the viewer.
- **Viewer panes:**
  1. source with the consumed token and lookahead highlighted differently
  2. token list (pending, consumed and pragma styled distinctly)
  3. parse tree outline (open path highlighted)
  4. scopes table plus the last 20 checks (✓/✗) and diags
  5. code listing (the last written address flashed; a `patch` shown as `old → new`)
- **Controls:**
  - ◀ / ▶ (also the ← → keys) and a slider over `0..n`.
  - "next/previous of kind": token, emit, check, diag.
  - "step over" (use `matchExit`) and "step out" (to the `exit` of the innermost open node).
  - An `Aborted` banner when relevant.
- Put the `Problem` text, when present, at the top of the page in plain words.

## 7. Bash scripts (`scripts/`, LF endings, `chmod +x`)

Every script starts with `#!/usr/bin/env bash` and `set -euo pipefail`, then sources
`scripts/lib.sh`. Portability rules:

- Quote every path. The project folder contains a space.
- `cd` to the project root and pass **relative paths only** to `java`, `javac` and `elm`. This
  avoids Git Bash path conversion of `/c/...` arguments.
- Use **exactly one classpath entry per command** (`-cp compiler`, `-cp compiler/tools-bin`),
  so the `;` vs `:` separator never matters.
- Put temporary files under `.tmp/` in the project (created with `mktemp -d .tmp/XXXX`), not
  under `/tmp`.
- The compiler asks `Interpret [y/N]?` on stdin when tracing is off. Always pipe `echo n |`
  into those runs.

| Script | Does |
|---|---|
| `lib.sh` | sets `ROOT`, `cd "$ROOT"`; `need java`, `need javac`, `need elm` with a friendly install hint; `die "msg"`; prints tool versions with `--verbose` |
| `import-compiler.sh [PRAC8_DIR]` | copies exactly the file set from §3 into `compiler/`. The default `PRAC8_DIR` is the Git Bash path from §0. It refuses to overwrite an existing `compiler/` without `--force`. |
| `build-compiler.sh` | in `compiler/`: `java -jar Coco.jar Parva.atg -options m` (as `cmake.bat` does) → move `Parser.java`, `Scanner.java`, `Parva.java` into `Parva/` → compile the tools into `tools-bin/` → run `Instrument` **only if** `Parser.frame` contains the begin marker → `javac -d . -nowarn Parva/*.java` (classpath `.`). Logs to `.tmp/build.log` and prints the last lines on failure. |
| `parva.sh <file.pav> [flags]` | same as `Parva.bat`: `java -cp compiler Parva.Parva …` |
| `trace.sh <file.pav> [out.json]` | runs with `-t`. The default output is `traces/<name>.json`. It fails if `selfCheck` is not `"ok"`. |
| `baseline.sh` | **Phase 0 only.** For each `compiler/examples/*.pav`: copy it to `.tmp`, run untraced with `echo n \|`, store `tests/baseline/<name>.cod`, `.out` (stdout) and `.exit`. It refuses to overwrite without `--force`. |
| `check.sh` | (1) For each example, run it untraced **and** traced; each `.cod`, stdout and exit code must equal the baseline. (2) Every trace has `"selfCheck": "ok"`. (3) The build log says `Instrumented 42 productions`. (4) `elm make` succeeds for both entry points (output to `.tmp`). It prints one `PASS`/`FAIL` line per item and a summary, and exits non-zero on any failure. |
| `trace-examples.sh` | traces every example into `traces/`, then runs `EmbedTraces` → `src/Stepper/Examples.elm` |
| `build-web.sh` | `elm make src/Stepper/Main.elm --optimize --output=stepper.html` and `elm make src/Main.elm --output=index.html` |
| `all.sh` | `build-compiler` → `check` → `trace-examples` → `build-web`. This is the single command a new user runs. |

## 9. Documentation style (for every file you write)

- **`docs/TRACE.md` is the only real document.** It contains the contract, the invariants,
  the minimum JDK and how to add a hook. Use tables over prose, short sentences and one idea
  per section. Do not write an architecture essay.
- **`compiler/CHANGES.md` is one table:** `file | line | change | why`, one row per `// TRACE`
  line.
- **Code comments are sparse.** Each new file gets a 1–3 line header saying what it is.
  Comment only lines whose purpose is not obvious, such as the dummy-token skip, the
  ISO-8859-1 decoding and the `finally` exit.
- **The README section is 25 lines or fewer.**

## 10. Things not to do

- Do not add a live debugger, JDI, a Java agent, a web server or WebSockets.
- Do not build a tree object in Java. The tree is derived in Elm from `enter`/`exit`/`consume`.
- Do not derive the tree by diffing stack traces. Two sibling calls of the same production
  have identical stacks.
- Do not log `Table.find` inside `Table.insert`, or nested helper calls inside
  `compatible`/`assignable`.
- Do not print anything from `Trace` to stdout.
- Do not touch `src/Main.elm`, `index.html` or the Prac8 folder.
